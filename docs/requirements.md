# ゲーム用画像加工ツール 要件定義書

- リポジトリ: [Pippiniden/Gazou-Shukushou](https://github.com/Pippiniden/Gazou-Shukushou)
- 文書バージョン: 1.0
- 作成日: 2026-10-23
- ステータス: 初期要件案

## 1. 概要

### 1.1 目的
ゲーム制作で使用する画像素材を、ブラウザ上で切り抜き、リサイズ、画質調整、形式変換して書き出せる無料の画像加工ツールを提供する。一般的な画像加工に加え、ゲーム用アイコン・カード素材・UIパーツなどの作成を想定する。

### 1.2 解決する課題
- 画像のピクセル寸法を指定して縮小・拡大したい。
- 画像の任意の範囲を視覚的に選択して切り抜きたい。
- 固定サイズの素材を作成し、必要に応じて余白や配置を調整したい。
- 透過画像のアルファチャンネルを維持したまま加工したい。
- 縮小方式やシャープネスを比較し、細い線や輪郭の劣化を抑えたい。
- 画像を外部サービスへアップロードせずに加工したい。

### 1.3 基本方針
- HTML / CSS / JavaScript を中心とするクライアントサイドアプリケーションとする。
- 画像データは原則としてブラウザ内で処理し、外部サーバーへ送信しない。
- インストール不要で、ローカル実行と静的ホスティングの両方に対応する。
- まず単一画像の加工を完成させ、その後に一括処理などを追加する。

## 2. 想定ユーザーと利用場面

### 2.1 想定ユーザー
- 個人ゲーム制作者
- Webゲーム・ブラウザゲーム制作者
- ゲーム用画像素材を準備するイラスト制作者
- アイコン、カード画像、UIパーツなどを規定サイズへ変換するユーザー

### 2.2 主な利用場面
1. 大きな画像から必要なパーツだけを切り抜く。
2. 任意の切り抜き範囲を指定サイズへ縮小または拡大する。
3. 画像の縦横比を維持しながら、指定寸法のキャンバスへ収める。
4. 透過を保ったPNG、容量を調整したWebP、またはJPEGとして保存する。
5. 加工結果をプレビューし、設定を変えながら見た目を比較する。

## 3. 機能要件

優先度は P0（初期版必須）、P1（初期版後の重要機能）、P2（将来拡張）とする。

### 3.1 画像の読み込み

| ID | 要件 | 優先度 |
|---|---|---|
| FR-001 | ファイル選択ダイアログから画像を読み込める。 | P0 |
| FR-002 | 対応ブラウザではドラッグ＆ドロップで画像を読み込める。 | P1 |
| FR-003 | 読み込み後、元画像の幅・高さを表示する。 | P0 |
| FR-004 | 読み込み失敗時にユーザー向けのエラーメッセージを表示する。 | P0 |
| FR-005 | JPEG、PNG、WebPを基本対応形式とし、ブラウザがデコード可能な一般的画像形式は可能な範囲で受け付ける。 | P0 |

### 3.2 切り抜き

| ID | 要件 | 優先度 |
|---|---|---|
| FR-010 | プレビュー画像上をドラッグして切り抜き範囲を指定できる。 | P0 |
| FR-011 | 切り抜き範囲を矩形で表示し、範囲外を暗くして選択範囲を視認できる。 | P0 |
| FR-012 | X座標、Y座標、幅、高さを数値入力して範囲を調整できる。 | P0 |
| FR-013 | 座標は表示上の縮尺ではなく元画像のピクセル座標を基準とする。 | P0 |
| FR-014 | 選択範囲が画像境界を超えないように制限する。 | P0 |
| FR-015 | 切り抜き範囲を画像全体へ戻せる。 | P0 |
| FR-016 | 範囲選択をやり直しても、元画像の画質を劣化させない。 | P0 |
| FR-017 | 将来的に固定アスペクト比や中央基準の範囲指定を追加できる設計とする。 | P1 |

### 3.3 リサイズ・キャンバス配置

| ID | 要件 | 優先度 |
|---|---|---|
| FR-020 | 出力幅と出力高さをピクセル単位で指定できる。 | P0 |
| FR-021 | 縮小と拡大の両方に対応する。 | P0 |
| FR-022 | 出力寸法の縦横比を維持するオプションを設ける。 | P0 |
| FR-023 | 縦横比の異なる入力を扱うため、次の配置モードを用意する。 | P0 |
|  | **変形（Stretch）**：切り抜き範囲を出力寸法いっぱいに描画する。 |  |
|  | **収める（Contain）**：縦横比を維持して全体を収め、余白を残す。 |  |
|  | **埋める（Cover）**：縦横比を維持してキャンバスを埋め、はみ出す部分を切る。 |  |
| FR-024 | 余白を含む出力では、余白の背景を透明または指定色にできる。JPEG出力時は透明を使用せず背景色で合成する。 | P1 |
| FR-025 | 出力ピクセル数の上限を設け、不合理に大きな入力によるメモリ不足を抑制する。 | P0 |
| FR-026 | 幅または高さの変更時に、縦横比維持設定に応じてもう一方の寸法を再計算する。 | P0 |

### 3.4 リサンプリング・画質調整

| ID | 要件 | 優先度 |
|---|---|---|
| FR-030 | 高品質、標準、低品質、最近傍補間を選択できる。 | P0 |
| FR-031 | 最近傍補間はドット絵やピクセルアート向けに提供する。 | P0 |
| FR-032 | 高品質モードはブラウザの高品質補間を利用する。アルゴリズムを厳密に固定できない場合は、その旨を仕様に記載する。 | P0 |
| FR-033 | 縮小後のシャープネス調整を追加可能な設計とする。 | P1 |
| FR-034 | 画質設定変更後、加工結果を再プレビューできる。 | P0 |
| FR-035 | 画質調整は元画像に対して非破壊で行い、設定変更のたびに元画像から再生成する。 | P0 |

### 3.5 プレビューと保存

| ID | 要件 | 優先度 |
|---|---|---|
| FR-040 | 加工後の画像をプレビュー表示する。 | P0 |
| FR-041 | 出力寸法と切り抜き寸法を表示する。 | P0 |
| FR-042 | PNG、WebP、JPEGを選択して書き出せる。 | P0 |
| FR-043 | WebPとJPEGでは品質を指定できる。PNGは可逆形式として扱い、非対応の品質指定を表示しない。 | P0 |
| FR-044 | 保存ファイル名に元ファイル名を引き継ぎ、加工済みであることが分かる接尾辞を付ける。 | P0 |
| FR-045 | ブラウザが指定形式を出力できない場合、失敗を検知して案内する。 | P0 |
| FR-046 | PNGの透過を維持する。JPEGでは背景色を合成して出力する。 | P0 |
| FR-047 | 可能なら加工前と加工後を並べて比較できる。 | P1 |

### 3.6 一括処理・プリセット

| ID | 要件 | 優先度 |
|---|---|---|
| FR-050 | 複数画像に同じリサイズ・形式設定を適用する。 | P1 |
| FR-051 | 一括処理では各画像に個別の切り抜き範囲を設定できる方式と、共通設定を適用する方式を検討する。 | P1 |
| FR-052 | 一括処理結果を個別保存、またはZIPでまとめて保存できる。 | P1 |

## 4. 画面要件

### 4.1 基本レイアウト
- PCでは、元画像・範囲選択エリアと、設定・加工後プレビューエリアを並べて表示する。
- 画面幅が狭い場合は縦一列に切り替える。
- 主な操作ボタンと状態表示を明確にし、設定項目を機能ごとにまとめる。
- 透明部分が見分けられるよう、プレビュー背景にチェッカーボード等を使用する。

### 4.2 画面領域
1. ヘッダー：ツール名、簡単な説明
2. 元画像エリア：画像読み込み、元画像情報、切り抜き操作
3. 範囲指定エリア：X、Y、幅、高さ
4. 出力設定エリア：寸法、縦横比、配置モード、補間方式、形式、品質
5. プレビューエリア：出力結果と寸法情報
6. 保存エリア：画像の書き出し
7. エラー・状態表示：読み込み、処理、書き出しの結果

## 5. 非機能要件

### 5.1 動作環境
- 最新版の主要ブラウザ（Chrome、Edge、Firefox、Safari）を優先対象とする。
- PCでの操作性を優先しつつ、スマートフォンでも基本的な切り抜きと保存を可能にする。
- ローカルのHTMLファイル、または静的ホスティングで動作する構成を基本とする。
- サーバー側処理、アカウント、データベースを必須としない。

### 5.2 プライバシー
- 画像の読み込み、加工、出力をクライアント側で完結させる。
- 画像データを外部サーバーへ送信しない。
- 外部ライブラリを追加する場合は、通信の有無、ライセンス、配布方法を確認する。

### 5.3 性能・安定性
- 画像サイズや出力寸法に上限を設け、処理前に過大なメモリ消費を抑制する。
- 処理中は操作状態を明示し、失敗時には再試行可能な案内を出す。
- 元画像を保持し、設定変更の累積による画質劣化を防ぐ。
- オブジェクトURLや一時キャンバスなど、不要になったリソースを適切に解放する。

### 5.4 保守性
- HTML、CSS、JavaScriptを適切に分離することを推奨する。初期版を単一HTMLにする場合も、処理単位ごとに関数を分ける。
- 切り抜き座標の計算、描画、形式変換、保存処理を独立させる。
- 追加ライブラリは必要性を検討してから導入する。

### 5.5 ライセンス
- 本体コードおよび依存ライブラリのライセンスを明示する。
- 依存ライブラリを導入する際は、商用利用・再配布条件を確認し、README等に記録する。

## 6. データと処理の仕様

### 6.1 切り抜き座標
- 座標系の原点は元画像の左上とする。
- X、Yは左上位置、幅、高さは正の整数とする。
- 範囲は元画像の境界内に収める。
- 表示用キャンバスの縮尺と元画像の座標を混同しない。

### 6.2 出力寸法
- 出力幅・高さは1以上の整数とする。
- 実装上の安全上限を設ける。初期値の上限案は各辺12,000pxとし、総画素数についても別途上限を設ける。
- 入力値が不正、空欄、上限超過の場合は補正または警告を行う。

### 6.3 画像形式
- PNG：透過維持を優先する素材向け。
- WebP：透過と圧縮効率を両立したい素材向け。品質設定により非可逆圧縮となる。
- JPEG：透過を扱わない写真等向け。透明部分は背景色に合成する。
- 拡張子は実際に生成されたMIME形式と一致させる。

## 7. 初期版の対象範囲

### 7.1 初期版に含める
- 画像読み込み
- ドラッグによる範囲選択
- 座標・寸法の数値指定
- 縮小・拡大
- 縦横比維持
- Stretch / Contain / Cover
- 高品質・標準・低品質・最近傍補間
- PNG / WebP / JPEG出力
- 透過維持
- プレビューと保存
- 入力値検証、基本的なエラー表示

### 7.2 初期版では対象外
- AIによる画像再構成や超解像
- 高度なレイヤー編集、マスク、ブラシ
- 自動背景除去
- スプライトシートの自動認識・分割
- クラウド保存、アカウント同期
- 複雑な色管理や印刷向けプロファイル管理

## 8. 受け入れ基準

| ID | 確認内容 | 合格条件 |
|---|---|---|
| AT-001 | 画像読み込み | PNG、JPEG、WebPを読み込め、元画像寸法が表示される。 |
| AT-002 | 範囲選択 | ドラッグで範囲を選択でき、表示と座標入力が一致する。 |
| AT-003 | 座標境界 | 画像外の座標や寸法が指定されても、範囲が画像境界内に補正される。 |
| AT-004 | 縮小 | 512×512の画像を256×256へ出力できる。 |
| AT-005 | 拡大 | 128×128の画像を256×256へ出力できる。 |
| AT-006 | 比率維持 | 縦横比維持を有効にした場合、指定した基準寸法に応じて比率が維持される。 |
| AT-007 | 配置モード | Stretch、Contain、Coverの各モードが想定どおり動作する。 |
| AT-008 | 透過 | 透過PNGをPNGとして出力したとき、透明部分が保持される。 |
| AT-009 | 形式変換 | WebP、JPEGで出力でき、拡張子が実際の形式と一致する。 |
| AT-010 | 最近傍補間 | 最近傍補間を選択したとき、ドット絵の輪郭がぼかされない。 |
| AT-011 | 非破壊編集 | 設定を複数回変更しても、元画像から再生成される。 |
| AT-012 | プライバシー | 通常の画像加工処理で画像データが外部送信されない。 |
| AT-013 | エラー処理 | 読み込み失敗や書き出し失敗時に、ユーザーが状況を理解できる。 |
| AT-014 | レスポンシブ | PCと狭い画面幅で主要操作が利用できる。 |

## 9. 開発ロードマップ案

### Phase 1：基本加工
- 画像読み込み、範囲指定、座標入力
- リサイズ、配置モード、プレビュー
- PNG / WebP / JPEG出力
- 透過とエラー処理

### Phase 2：画質と操作性
- 補間方式の比較
- シャープネス処理の品質検証
- 背景色・余白設定
- プレビュー比較、操作の改善

### Phase 3：作業効率化
- 複数画像の一括処理
- ZIP出力
- プリセットの保存・読み込み
- 必要に応じてスプライトシート分割を追加

## 10. 未決事項

実装開始後、必要性を見ながら決定する。

1. 一括処理を初期版に含めるか、Phase 3に回すか。
2. シャープネス処理に専用ライブラリを使うか、自前実装とするか。
3. 余白の位置合わせ（中央、上下左右、任意位置）をどこまで提供するか。
4. 出力寸法と総画素数の安全上限を、想定ブラウザや利用画像に合わせてどう設定するか。
5. 設定プリセットをブラウザ内に保存するか、JSONファイルとして入出力するか。
6. 対応するブラウザ・端末の最低バージョンをどこに定めるか。

## 11. 実装上の注意

- Canvasの標準補間はブラウザごとに実装差があり、「Lanczos」と指定して厳密に保証できるわけではない。厳密なLanczos処理が必要になった場合は、実装または依存ライブラリを別途選定する。
- シャープネス処理はノイズや輪郭のハローを強調することがあるため、初期状態では無効とし、画質検証を行う。
- JPEGは透過を保持できない。出力時に背景色を明示的に合成する。
- 画像寸法だけでなく総画素数と処理時の一時メモリも考慮し、極端に大きな画像に対する安全策を実装する。
- 要件定義書は初期案であり、実際の操作テストで得られた結果をもとに更新する。
